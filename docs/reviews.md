# Reviews

Each stage was checked twice before it was merged: first by the builder against its own audit checklist, then by an independent reviewer that had not written the code. The fix pull requests after the manual tests were checked by the pre-delivery and final audits of the release; some of those audits ran after the pull requests they covered were merged. The reviewers were Codex and separate Claude Code sessions with read-only instructions. Each pinned a commit, ran the gates itself, and wrote findings with a severity, a location and evidence. Every finding was then fixed on the branch it belonged to, with a test that fails without the fix, or answered in writing with a reason.

The full reports stay outside the repository, because they contain paths and notes from the build machine. This page is the public summary, and it explains the finding IDs that appear in commit messages. IDs are only unique within their round: "F1" in the PR #1 review is not "F1" in the manual test.

Other IDs in commit messages:

- **D-NNN:** a decision; see [decisions.md](decisions.md).
- **B-NNN:** an item from the build backlog, for example B-030 (copy a card as Markdown) and B-031 (the document-control form).
- **S-NN:** an item from the security plan, for example S-26 (instructions that could be unsafe to follow).
- **Guardrail N:** one of seven product guardrails checked before the video, for example Guardrail 3: no warehouse-specific code, the demo's domain lives in `demo-data/` and the card template.
- **TC-XXX-NNN:** a test case in [testing.md](testing.md).
